## README

# lang33 — 33 天语言自学站生成框架

把任意语言做成一个**离线可用、无需注册、手机可读、界面双语可切换**的自学站：
认字 → 拼句子 → 拆语法 → 开口说，每天知道练什么。

> 这不是又一个背单词工具。核心是那个别人不做的模块：**句子结构 + 造句组装台**——
> 学习者最卡的从来不是词不够，是不知道词怎么摆。

## 30 秒起步

```bash
python3 scripts/scaffold.py --out ~/ja-study \
  --lang-native "日本語" --lang-zh 日语 --lang-en Japanese \
  --speech ja-JP --favicon 日 --sample "はじめまして"

python3 -m http.server 8800 -d ~/ja-study     # 打开 http://127.0.0.1:8800
```

生成的站点当场能跑（内含自明的占位数据），然后按 `SKILL.md` 的五步把数据换成真的。

## 站点包含什么

33 天路线图 · 发音规则 · **句子结构（含造句组装台）** · 语法卡片 · 词汇表 ·
Leitner 五盒闪卡 · 现场生成的测验 · 9 条 AI 陪练提示词
＋ 深浅色主题 · 两种界面语言随时切换 · 手机自适应 · 进度只存本地。

纯静态：无框架、无构建工具、无外部请求，`file://` 双击也能开。

## 为什么值得用

数据流水线自带校验，**校验不过就拒绝生成**：

- 两种界面语言**双向**覆盖检查（缺翻译是错，多出来的拼错键也是错）
- 例句数量、提示词变量集合一致性
- 造句组装台的活用形空格、动词-宾语搭配、时态-时间词冲突
- 转写/发音由引擎生成，不许手打；双实现（Python + JS）强制 parity 测试

方法论和 15 个真实踩坑记录在 `SKILL.md`，细节在 `references/`。

## ⚠️ 执行前必读（错误段）

这些坑是在真实建站过程中踩出来的，不是设想出来的。**动手前先读完**。

- **E001 只做「提示词展示页」= 壳。** 起点如果是一条「用 6 条提示词学会 X 语」的推文，照搬提示词做个页面没有价值——提示词补不了「认字 / 音变 / 语法 / 造句」。提示词只该是站点里的一个模块。
- **E002 领域硬数据不能凭记忆手打。** 罗马音、音变、词义、语法接续全部要么由算法生成、要么逐条对照权威源。写错一个字母表，整站的可信度归零。做法见 `references/02-data-verification.md`。
- **E003 「40/40 通过」要拆开报。** 韩语罗马音回归测试 40 条里有 5 条是命中我自己写的例外表——那 5 条不算算法验证通过。**自查结果必须分开报「纯算法通过 / 命中例外表」**，否则是自欺。
- **E004 同一个音位类别要铺开测，不能单点抽查。** 韩语 ㅀ 连音写错（싫어 给出 sileo，应 sireo），而同类的 ㄶ 因为前后同音把错误掩盖了。按音素类别成批验证才发现得了。
- **E005 「转写」和「实际发音」是两条通道。** 罗马字标准常常明文规定不反映某些音变（如韩语紧音化），但学习者必须听得出。混成一个函数，规则页就会显示「학교 → 학교」等于没教。拆成 `rr()` 和 `pron()`。
- **E006 双实现必须有 parity 测试。** 构建期用 Python、页面用 JS 各写一份引擎，改一边忘另一边是必然会发生的事。韩语站的 parity 覆盖 1336 样本 × 9 函数 = 12024 项，跑一次几秒。
- **E007 连音规则里的「空位辅音」是陷阱。** 韩语 ㅇ 作收尾音时**不能**移到下一格（강아지 不是 가아지）——因为初声 ㅇ 不发音，一移动整个音就消失了。这个 bug 让 4 个词的罗马音错了（병원 byeowon / 공원 gowon …），是靠造句组装台的实际输出才暴露的。**任何「把尾辅音移到下一个音节」的规则，先问：有没有本身不发音的辅音？**
- **E008 双语站最容易漏的是「拼在一起的字符串」。** 例句注解写成 `"저는 = 我 / I"` 这种一行双语，切到英文界面时中文会漏出来。**所有面向人的字符串都要按语言分开存**，不能靠拼接。
- **E009 界面语言键要机器校验。** 两份语言字典靠人对不齐。`tools/check_i18n.js` 做三件事：两语言键集合完全一致 / 代码里用到的键都存在 / 占位符 `{0}` 个数一致。改文案后必跑。
- **E010 数据里的对象别直接丢进模板。** 动词条目的 `en` 是 `{base,s,past}` 对象，走通用「取当前语言」函数会渲染成 `[object Object]`。渲染前先想清楚这个字段是字符串还是结构。
- **E011 造句组装台不能用算法现推活用形。** 变位/活用错一个字就是在教错。所有活用形写成**手工校对过的闭集**（每个动词 × 每个时态一格），构建期检查有没有空格子。
- **E012 组合要加语义闸门。** 「보다 + 책」在韩语自然，翻成英文却成了 "watch a book"；「고 싶어요」第三人称主语不合语法。**动词要声明能带哪些宾语，时间词要声明能配哪些时态**，构建期校验，界面上自动纠正并告知用户。
- **E013 存进 localStorage 的索引会越界。** 数据条目变少后，上次选中的第 4 个位置就不存在了 → 整个模块白屏。渲染前先 clamp。
- **E014 混排字符要清干净。** 韩语课程标题写成 `해요体`（韩文 + 汉字「体」），中文界面看着正常，英文界面就露馅。对照语言文字表扫一遍。
- **E015 手机测不了就别猜。** macOS 上 Chrome 窗口有最小宽度，`--window-size=390` 的 headless 截图会**按更宽的视口排版再裁掉右边**，看起来像溢出其实不是。可靠办法：开一个 390px 宽的 iframe 装载站点，量 `scrollWidth == clientWidth`。
- **E016 统一 CSS 类名时会误伤后代选择器。** 把 `.ko-s` 统一成 `.tl` 之后，`.order-row .ko`（本意只管那一整行大字，24px）变成了 `.order-row .tl`，把注解小标签里的目标语言文字也一起放大成 24px，一大一小很难看。**病根：同一个名字既当"字体类"又当"结构类"。** 改名前先分开：字体类（`.tl`）只管字体，结构位置用独立类（`.line`）。改完把所有 `.<新名>` 选择器逐条看一遍，不能只看编译通过。
- **E017 临时测试文件不要放进项目目录。** 量手机排版的探针页（390px iframe）放在了站点根目录，被当成"网页版"打开过，删掉之后浏览器缓存还在继续显示 → 白白解释两轮。临时文件放临时目录，站点目录只放会发布的东西。
- **E018 自检命令本身会造假数据。** `curl -w "a=%{http_code} b=%{http_code}"` 一次请求会把**同一个**状态码填进两个占位符，看起来像"两个页面都 404"，差点据此报"站点坏了"。**一次请求只测一件事**；要测两个 URL 就发两次。同类形态：把同一个变量当成两个来源的证据（AS4：不确定时默认可能有问题）。

## 这个框架产出什么

一个纯静态站点（无构建工具、无框架、无外部请求），包含 8 个模块：

| 模块 | 回答学习者的什么问题 | 数据来源 |
|---|---|---|
| 33 天路线图 | 今天到底该干什么 | `CURRICULUM` |
| 发音规则 | 为什么写的和读的不一样 | `PHONOLOGY` + 引擎 |
| **句子结构** | 词都会了，怎么拼成句子 | `SENTENCE`（本框架的核心） |
| 语法卡片 | 这个语法点到底在干什么 | `GRAMMAR` |
| 词汇表 | 高频词 + 真实读音 | `DECKS` |
| 闪卡 | 怎么背才不忘（Leitner 五盒） | 同上，进度存 localStorage |
| 测验 | 我哪块最弱 | 由以上数据**现场生成** |
| AI 陪练 | 没人纠错怎么办 | 9 条提示词，填空即用 |

外加：深浅色主题、两种界面语言随时切换、手机自适应、进度只存本地不上传。

## 用法

### 1. 生成骨架（30 秒）

```bash
python3 scripts/scaffold.py --out ~/ja-study \
  --lang-native "日本語" --lang-zh 日语 --lang-en Japanese \
  --speech ja-JP --favicon 日 --sample "はじめまして"
```

生成的站点**当场就能跑**（内含自明的占位数据）：

```bash
python3 -m http.server 8800 -d ~/ja-study   # 打开 http://127.0.0.1:8800
```

### 2. 按五步填数据（顺序不要换）

顺序是有理由的：**先能造句，再谈其它**。学习者最快的正反馈是「我拼出了一句真话」。

1. **句子结构**（`SENTENCE`）— 语序 / 位置 / 原理 / 10–15 个句型 / 生长梯 / 组装台
2. **词汇**（`DECKS` + `vocab_en.py`）— 按场景分 8–10 组，300–400 词就够「撑到能开口」
3. **语法**（`GRAMMAR` + `content_en.py`）— 30–40 条，每条必须写「母语者最容易犯的错」
4. **发音规则**（`PHONOLOGY`）— 只收「写的和读的不一样」的规则；没有这种现象的语言可以留空
5. **33 天路线**（`CURRICULUM`）— 见 `references/03-curriculum-33.md` 的排法

每改一次跑：

```bash
python3 tools/build.py        # 数据校验 + 生成 data/*.js（有问题就拒绝写文件）
node tools/check_i18n.js      # 两种界面语言的文案对齐
```

### 3. 有自己的文字/音变的语言，再加引擎和模块

拉丁字母语言可以跳过这步（默认适配器是恒等函数）。日语/韩语/阿拉伯语/泰语/俄语需要：

- **引擎**：`tools/<lang>_core.py`（构建期）+ `assets/js/<lang>-engine.js`（页面），提供 `rr()` / `pron()` / `has_final()`；
  页面在 `script-adapter.js` **之前**加载并设置 `window.ScriptEngine`；写 parity 测试（E006）
- **额外页面**（字母表 / 组字器…）：`assets/js/modules/<lang>-alphabet.js` 往 `window.Views` 挂函数 +
  `index.html` 加 `<section class="view" id="v-alphabet">`。**路由自动发现**，不用改框架
- **额外题型**：`Views.registerQuizKind('jamo', maker)`，标签用 i18n 键 `quiz.kind.jamo`

参考：韩语站 `assets/js/modules/hangul-alphabet.js`（字母表 + 组字器 + 自模拟题型，约 190 行）。

### 4. 框架升级：改模板，不要改项目

```bash
python3 scripts/sync.py --project ~/ko-study          # 把 templates/ 的更新推下去
python3 scripts/sync.py --project ~/ko-study --check  # 有人在项目里改了框架文件 → 报错
```

框架文件（`views.js` / `app.js` / `style.css` / `build.py` …）由 sync 管；
项目文件（`index.html` / `data/*` / `tools/*_source.py` / `modules/*` / `lang.css`）随便改。

## 硬规则（违反=返工）

1. **数据不手打** — 转写/发音由引擎生成；词义逐条对照词典；查不到的**列出来让人判断，不要静默删掉**。
2. **双向覆盖检查** — 缺翻译是错，多出来的键（拼错）也是错。`build.py` 两个都拦。
3. **成色分开报** — 「算法验证通过 N 条 / 命中例外表 M 条」分开写。合并报数就是造假。
4. **闭集优先于算法** — 教学内容里出现的活用形宁可手写闭集，也不要现推。
5. **每个模块都要能独立回读** — 构建脚本打印真实数字（几条规则、几个词、几种组合），一眼能看出有没有少。
6. **交付前自己跑一遍** — 起服务器点开每个页面、两种语言各切一次、在 390px 宽度量一次溢出。
