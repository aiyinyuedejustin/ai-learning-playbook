# 授课加小测

目的：一次把一个节点讲明白，然后用一两道小题确认"不是只是看懂了"。考是为了发现缺口，不是为了拦人。

## 先读这些

- 主题文件夹里的 `goal.md`（画像、终点）、`map.md`（下一个节点）、`gaps.md`（已有缺口，讲新内容时顺手补）、`log.md` 最近几条。
- 用户的 `preferences.md`，有就照它来。

## 步骤

1. **选节点。** 默认讲 `map.md` 里第一个"未学"的节点；用户点名就讲他点的。如果它依赖的前置在 `gaps.md` 里还开着，先花两三句把那个前置补上。

2. **先讲。** 讲义写成一个 md 文件，放在主题文件夹的 `lessons/` 下，文件名带序号，比如 `lessons/03-回程.md`。同时在对话里给出要点。讲义的结构：
   - **为什么需要它**：它解决什么问题，不懂它会碰到什么麻烦。
   - **讲清楚**：先一句话说结论，再展开。用用户画像里已有的知识打比方。行话第一次出现时当场解释。
   - **一个具体例子**：真实场景、真实数字或真实命令。
   - **和已学内容的联系**：一两句话，连到之前的节点。
   - **常见误解**：一两条。

   讲义要短，一个节点一般读完五分钟以内。文字说不清的东西（流程、结构、对比），配一张 Draw.io 图（见 `learn-map` 里的画法）。

3. **需要时再出 HTML 测验。** 默认不做。遇到下面情况可以提议做一个单文件 HTML 小测验或小演示，放在 `lessons/` 里：要拖动、调参数才看得懂的东西；用户主动想要；同类题需要反复练。用户同意再做。

4. **再考，轻一点。** 讲完当场出一到两道题：
   - **技能类**（会操作、会算、会写）：给一两道小题或小任务。
   - **概念类**：请用户用一句话说出核心意思，或者回答一个"如果没有它会怎样"。
   - 题型不写死。简答、应用题、选择题都行，按主题选；拿不准用户想要哪种时，直接问一句。
   - 用户可以语音碎碎念作答，判断时看意思，不挑措辞。

5. **判和记。**
   - 答对：一句话肯定，指出答得最好的那一点。
   - 答错或答不上来：给正确答案和一句解释，然后把这个点记进 `gaps.md`（写清用户原来怎么想的），继续往下走，不要求重做，不卡着。
   - 用户说"跳过不考"，就跳过，在 `log.md` 里记"未考"。

6. **记录。** 按 `learn-track` 的格式：`log.md` 加一条，`map.md` 里这个节点的状态改成"已学"或"有缺口"。

7. **问下一步。** 一句话问：继续下一个节点、先停在这里，还是想动手练一下。不限时长，用户想学几个就学几个。

## 动手练习

不强制动手。用户说想练的时候，帮他设计，原则是先零成本，再低成本：

- 先找完全免费的练法：本机就能跑的命令，网页上的在线模拟器或演练场，本地虚拟机或容器。
- 必须花钱时，给出最便宜的做法和大致花费，提醒用完关掉或删除，免得一直扣费。
- 每个练习写清：要做什么、预期看到什么结果、看到什么说明懂了、出问题先查哪里。
- 例子：学 VPS 和 Linux 命令，可以先在本机用 Docker 或虚拟机开一个 Linux 练命令，用自己电脑跑 `traceroute`/`mtr` 看网络路径；真要买 VPS，挑按小时计费的最低配，练完删掉。
- 练习方案也写进讲义末尾，方便以后回来做。
