# 速读报告

目的：给一个主题，交一份用户从头读到尾就能大致懂的报告。没有会话、没有进度表，读完就完。

## 先读这些

- 用户的 `preferences.md`，有就照它来。
- 如果这个主题已经有文件夹（`goal.md` 等），读一下画像，按他已经会的程度写，跳过他已经懂的部分。

## 步骤

1. **搞清楚问的到底是什么。** 题目里如果是两三个词放在一起（比如"VPS 和线路"），先想清楚它们为什么会一起出现、用户多半是在什么场景下碰到的，报告就围绕这层关系来写。实在看不出来，问用户一句；能猜出常见场景就不问，直接写，并在开头说明按哪个场景写的。

2. **找资料，核对事实。** 至少看两三份可靠来源再写，不全靠记忆。会变的东西（价格、产品名、套餐、版本号）要么不写，要么写明"会变，以官方为准"。厂商或卖家写的科普可以参考，但要注明是商家来源。资料是视频的，用 `video-transcript-sources` skill 或别的字幕工具先转成文字。

3. **写报告。** 存成 md，文件名用主题短名，比如 `vps-and-routes.md`，放在用户指定的位置（没说就当前目录）。结构由浅入深：
   - **一句话版本**：整篇的结论，读完这句就知道个大概。
   - **背景**：这东西是为了解决什么问题出现的，用户在什么场景下会碰到。
   - **整体结构**：几个核心概念和它们之间的关系。这里适合放一张图。
   - **细节**：逐个讲核心概念。每个概念：是什么、打个比方、一个具体例子、常见误解。
   - **行话速查表**：这个领域里常见的缩写和黑话，一行一个，一句话解释。圈内人说话常用代号，看不懂代号就看不懂别人的讨论。
   - **怎么用上**：学完能做什么判断，具体怎么做；用户想动手的话，有什么零成本或低成本的练法。
   - **自测题**（可选）：三到五道，答案折叠在后面或放在文末。
   - **参考资料**：列出用到的来源。

   全文用平实的话写，行话第一次出现时当场解释。长度以读完不超过二十分钟为宜。

4. **需要时配图。** 有结构或流程要说明时，用 Draw.io 画一张（做法见 `learn-map`：原生 `.drawio` 文件，能导出就导出 PNG，检查中文没有乱码），图和报告放在一起。只是罗列几个点的，不必画图。

5. **交付。** 告诉用户报告在哪，再用两三句话说出最重要的结论。最后提一句：想系统学、要记录哪里没懂，可以接着用完整版（从 `learn-probe` 开始），这份报告可以当它的参考资料。
