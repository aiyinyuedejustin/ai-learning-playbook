# 记录进度和缺口

目的：让用户随时知道学到哪了、哪些还没弄懂，下次回来接着学时不用从头想。只靠四个 md 文件，不用卡片软件，也不定时提醒。

## 文件夹结构

```
<学习仓库>/
  preferences.md            用户的个人偏好（全局一份）
  learning/
    <主题短名>/
      goal.md               目标、学习者画像、起点
      map.md                学习阶梯图 + 进度表
      map.drawio / map.png  地图源文件和图片
      log.md                每次学习的记录
      gaps.md               缺口清单
      lessons/              每个节点的 md 讲义（可选 HTML 测验）
```

学习仓库的位置第一次问用户；没说就用当前目录。本目录 `assets/` 下有四个文件的空白模板。

## 四个文件各写什么

**goal.md**：由 `learn-probe` 写，之后很少改。用户的目标变了才更新，并在 `log.md` 里记一笔。

**map.md**：图 + 进度表。进度表每行一个节点，"状态"只用这几个值：已会（摸底时就会）、未学、在学、已学、有缺口。每次讲完一个节点就改这一栏。表下面加一行汇总：已学几个 / 共几个，开着的缺口几个。

**log.md**：倒序记录，最新的在最上面。每条三到五行：
- 日期（用户本地时间）和做了什么（摸底 / 讲了哪个节点 / 诊断 / 动手练习）；
- 小测结果：对、错、未考；
- 用户说过的一句有代表性的话（原话），方便以后诊断误解；
- 下次从哪里接着学。

**gaps.md**：缺口清单，用表格。每行：缺口（一句话）、用户原来怎么想的、属于哪个节点、来源（小测 / 摸底 / 自己提的）、状态（开着 / 已补上）。补上了不删，改状态并写一句怎么补上的。

## 步骤

1. 确认主题文件夹存在；不存在就按上面的结构从模板建好。
2. 按刚发生的事更新对应文件：讲完节点改 `map.md` 状态 + 写 `log.md`；有答错的加进 `gaps.md`；缺口被补上就改状态。
3. 如果学习仓库是 git 仓库，用一句清楚的提交说明提交（比如"vps-and-routes：学完回程，新增 1 个缺口"）。推送前问用户一次，之后按他的回答来。
4. 用户问进度时，读 `map.md` 和 `gaps.md`，回答三句话：学到哪了，还剩几个节点，开着几个缺口、最要紧的是哪个。

## 不做的事

- 不做闪卡，不接 Anki，不排记忆曲线复习。复习靠回来翻 `gaps.md`。
- 不设定时任务，不主动推送提醒。
- 用户以后想加卡片或提醒，改 `preferences.md`，再改这个 skill。
